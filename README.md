# M휘트니스 웹 (운영 보드 · 급여 정산)

Claude 아티팩트로 쓰던 두 화면을 **Firebase Hosting + Firestore** 로 옮긴 것입니다.
이제 데이터는 Claude가 아니라 우리 Firebase 프로젝트에 쌓입니다.

| 파일 | 화면 | 배포 후 주소 |
|---|---|---|
| `public/index.html` | 운영 보드 (방문자·문의·업무일지·OT·회의록·근무당직·사물함) | `https://<프로젝트id>.web.app/` |
| `public/payroll.html` | 급여 정산 (직원/관리자 PIN 로그인) | `https://<프로젝트id>.web.app/payroll.html` |

---

## 1. 준비 (한 번만, 약 15분)

### 1-1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 접속 → **프로젝트 추가**
2. 이름은 아무거나 (예: `m-fitness`). Google 애널리틱스는 **사용 안 함**으로 둬도 됩니다.

### 1-2. Firestore 만들기
1. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
2. **프로덕션 모드**로 시작 (규칙은 아래에서 넣습니다)
3. 위치는 **asia-northeast3 (서울)** 선택 — 한 번 정하면 못 바꿉니다.

### 1-3. 익명 로그인 켜기
1. **빌드 → Authentication → 시작하기**
2. **Sign-in method** 탭 → **익명(Anonymous)** → 사용 설정 → 저장

> 두 화면 모두 열릴 때 자동으로 익명 로그인을 합니다. 직원이 따로 할 일은 없습니다.

### 1-4. 웹 앱 등록하고 설정값 복사
1. **프로젝트 설정(톱니바퀴) → 내 앱 → 웹(`</>`)** 선택, 닉네임 아무거나 입력
2. 화면에 나오는 `firebaseConfig` 값을 복사
3. `public/firebase-config.js` 를 메모장으로 열어 **따옴표 안만** 채우고 저장

```js
window.FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "m-fitness.firebaseapp.com",
  projectId: "m-fitness",
  storageBucket: "m-fitness.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef"
};
```

이 값들은 비밀번호가 아닙니다. 공개돼도 괜찮고, 실제 통제는 `firestore.rules` 가 합니다.

콘솔 화면의 코드를 통째로 복사해 붙여넣어도 됩니다 (`const firebaseConfig = { ... };` 형태 그대로 인식합니다).
다만 `import` 로 시작하는 줄이 섞여 있으면 그 줄은 지워야 합니다.

값이 비었거나 파일이 같이 안 올라가면, 화면 아래쪽에 둘 중 무엇이 문제인지 구분해서 표시됩니다.

## 2. 배포

### 방법 A — Firebase CLI (권장)

```bash
npm install -g firebase-tools
firebase login
cd <이 폴더>
firebase use --add        # 위에서 만든 프로젝트 선택
firebase deploy           # 페이지 + 보안 규칙 한 번에 배포
```

끝나면 터미널에 `https://<프로젝트id>.web.app` 주소가 나옵니다. 직원 4명에게 그 주소를 공유하면 됩니다.
이후 파일을 고칠 때마다 `firebase deploy` 만 다시 실행하면 됩니다.

### 방법 A-1 — GitHub Actions로 자동 배포 (지금 이 사이트가 쓰는 방식)

`main` 브랜치가 바뀔 때마다 `.github/workflows/deploy-hosting.yml` 이 자동으로
**Firebase Hosting**에 배포합니다. Firebase Hosting은 이 저장소가 이미 쓰고 있는
Firebase 프로젝트에 포함된 기능이라 **별도 가입이나 결제 수단 등록이 필요 없고**,
Netlify처럼 배포마다 별도로 과금되는 "크레딧" 개념도 없습니다(무료 한도: 하루
전송량 360MB, 저장 10GB — 직원 4명 사용량엔 사실상 무제한).

한 번만 설정하면 됩니다:

1. **서비스 계정 키 만들기**: Firebase 콘솔 → 프로젝트 설정(⚙️) → **서비스 계정** 탭 →
   **새 비공개 키 생성** → JSON 파일이 다운로드됩니다.
2. **GitHub에 비밀값 저장**: 이 저장소 → Settings → Secrets and variables → Actions →
   **New repository secret** → 이름 `FIREBASE_SERVICE_ACCOUNT`, 값에는 방금 받은
   JSON 파일 내용을 **그대로 전체 복사해서** 붙여넣기
3. https://github.com/jiyoon7653/mfitness/actions 에서 **Firebase Hosting 자동 배포**를
   선택해 **Run workflow** 로 한 번 수동 실행해서 정상 배포되는지 확인
4. Firebase 콘솔 → Authentication → **설정 → 승인된 도메인**에
   `<프로젝트id>.web.app` 이 이미 기본으로 등록되어 있는지 확인 (보통 자동으로 들어가 있습니다)

이후로는 코드가 고쳐져서 `main`에 올라갈 때마다 몇 초 안에 같은 주소
(`https://<프로젝트id>.web.app`)에 새 버전이 올라갑니다. 서비스 계정 키는
비밀번호와 같으니 GitHub Secret 외에는 어디에도 붙여넣지 마세요.

**참고 — 새로 만든 이 워크플로가 방법 B-1(Netlify)의 자동 배포를 대체합니다.**
Netlify를 계속 켜둘 필요가 없다면 Netlify 대시보드에서 **Site settings →
Danger zone → Delete site**로 정리하고, `netlify.toml` 파일도 지워도 됩니다
(안 지워도 동작에는 지장 없습니다 — 그냥 안 쓰는 설정 파일로 남을 뿐입니다).

### 방법 B — CLI 없이

1. **보안 규칙**: 콘솔 → Firestore Database → **규칙** 탭 → `firestore.rules` 내용을 붙여넣고 **게시**
2. **페이지**: `public/` 안의 세 파일(`index.html`, `payroll.html`, `firebase-config.js`)을 원하는 정적 호스팅
   (Netlify, Cloudflare Pages, 기존 웹호스팅의 `html` 폴더 등)에 그대로 올립니다.
   세 파일은 **같은 폴더**에 있어야 합니다.
3. Firebase 콘솔 → Authentication → **설정 → 승인된 도메인**에 그 호스팅 도메인을 추가하세요.
   (이걸 빠뜨리면 로그인이 막혀서 저장이 안 됩니다.)

### 방법 B-1 — Netlify에 GitHub 저장소 연결 (더 이상 쓰지 않음, 참고용)

매번 zip을 받아서 드래그하는 대신, 한 번만 연결해두면 그 뒤로는 이 저장소의
`main` 브랜치가 바뀔 때마다 Netlify가 알아서 새로 배포합니다.

**주의 — Netlify는 배포마다 "크레딧"을 씁니다.** Netlify의 최신 요금제는 빌드
시간·대역폭 등을 통합한 크레딧 방식이라, 개발 중 자주 배포하면 무료 한도를
금방 채울 수 있습니다(실제로 이 프로젝트도 이 문제로 방법 A-1로 옮겼습니다).
Firebase Hosting(방법 A-1)에는 이런 배포당 과금이 없으니, 새로 설정한다면
Netlify 대신 방법 A-1을 쓰세요.

1. https://app.netlify.com 로그인 → **Add new site → Import an existing project**
2. **Deploy with GitHub** 선택 → 처음이면 GitHub 인증 화면이 뜹니다 → 저장소 목록에서
   `jiyoon7653/mfitness` 선택
   (목록에 안 보이면 "Configure the Netlify GitHub App" 링크로 들어가 저장소 접근 권한을 추가하세요)
3. 배포 설정 화면 — 저장소에 `netlify.toml` 파일이 있어서 **Publish directory가 자동으로
   `public` 으로 채워집니다.** Build command는 비워둔 채로 **Deploy** 클릭
4. 몇 초 뒤 배포되고 주소가 나옵니다. Site settings에서 **Change site name** 으로
   원하는 이름으로 바꿀 수 있습니다 (예: `mfitness.netlify.app`)
5. Firebase 콘솔 → Authentication → **설정 → 승인된 도메인**에 이 Netlify 주소를 추가하세요

이후로는 **아무것도 안 하셔도** 됩니다 — 코드가 고쳐져서 `main`에 올라갈 때마다
Netlify가 1분 내로 같은 주소에 새 버전을 올립니다. Netlify 대시보드의 **Deploys** 탭에서
배포 이력을 볼 수 있습니다.

## 3. 데이터가 어떻게 쌓이나

**운영 보드** — 아티팩트에서 쓰던 것과 같은 구조 그대로입니다.

| 컬렉션/문서 | 내용 |
|---|---|
| `visitors` | 방문자·예약자 (건별 문서) |
| `inquiryCalls` | 문의 전화 (건별 문서) |
| `worklogs` | 업무일지 + 매출 (건별 문서) |
| `lockers` | 사물함 (건별 문서) |
| `otSessions` | OT 진행 인원 (건별 문서: 트레이너, 고객명, 연락처, 회차, 진행상황, 전환여부) |
| `meetings` | 회의록 (건별 문서: 날짜, 종류, 참석자, 안건, 결정사항, 액션) |
| `settings/salesCategories` | 매출 카테고리와 월 목표 · 1~5주차 목표 |
| `settings/otTrainers` | 트레이너별 OT 월 목표 · 1~5주차 목표 |
| `settings/monthlyFocus` | 이달의 집중 항목 |
| `settings/dutyRoster` | 당직표 (`"2026-09-05": { person, note }` 형태의 지도) |
| `settings/leaves` | 월차·연차·휴무 사용 기록 (`"날짜_이름_구분"` 키) |
| `settings/dutyEvents` | 그 밖의 근무 일정 (동원훈련·공사 등, `"날짜__고유값"` 키) |
| `settings/dutyStaff` | 당직·휴가에 나오는 직원 명단 |
| `settings/lockerSnapshot` | 사물함 엑셀 대조 결과 (마지막으로 불러온 것) |
| `settings/lockerNotified` | 사물함 재등록 문자 발송 체크 (`"사물함번호": "발송일"`) |

> 당직·휴가·사물함 대조는 **컬렉션이 아니라 `settings/` 문서 안의 지도(map)** 에 담습니다.
> 이렇게 하면 (1) Firestore 규칙(`match /settings/{doc}`)을 손대지 않아도 바로 동작하고,
> (2) 키 단위 `merge` 로 저장하기 때문에 **두 사람이 동시에 다른 주차를 고쳐도 서로 덮어쓰지 않습니다.**

여러 명이 동시에 봐도 실시간으로 같이 갱신됩니다 (`onSnapshot`).

**운영 보드 사용법 — 매출·업무일지 탭**
- **월 목표와 1~5주차 목표를 카테고리별로 미리 설정**합니다. "카테고리·목표 수정"을
  누르면 카테고리마다 월 목표 한 칸과 **1주차~5주차 목표 다섯 칸**이 나옵니다.
  미리 채워두면 **매주 해당 주차 목표가 자동으로 적용**됩니다 (이번 주에 해당하는
  칸은 파란 테두리로 표시됩니다). 주차 기준은 **그 주 월요일이 속한 달**의 몇 번째
  주인지입니다 — 주간 집계 범위(월~일)와 같은 기준이라 경계가 어긋나지 않습니다.
- **"목표 대비 달성"은 이제 토글 없이 이번 달(고정)과 이번 주(자동으로 항상 이번 주)를
  동시에 보여줍니다.** 표 위에 카테고리별 카드가 있고, 카드마다 **월/주 달성률을
  원형 게이지 2개**로 한눈에 보여줍니다 — 초록(100%↑)·주황(70%↑)·빨강(그 아래)으로
  색이 바뀌어서 숫자를 안 읽어도 상태를 바로 알 수 있습니다. 표는 정확한 금액이
  필요할 때 그 아래에서 확인하면 됩니다.
- **누적 업무일지**는 원래도 전체 기록이 자동 저장돼 있었지만, 이제 화면에서 바로
  다루기 쉽게 두 가지를 추가했습니다: 목록 위의 **월 선택**으로 지난 달 기록만 걸러
  보고, **행을 클릭**하면 그날 카테고리별 매출 내역이 펼쳐집니다.
- 업무일지의 "당일 OT 개수" 칸은 없앴습니다. OT는 이제 아래 **OT 관리** 탭에서
  인원별로 따로 기록합니다 — 뭉뚱그린 숫자 하나가 아니라 실제 인원 데이터로
  누적됩니다.
- **매출·업무일지 탭은 비밀번호로 들어갈 때마다 매번 다시 확인**합니다. 예전에는
  한 번 입력하면 창을 끄기 전까지 계속 열려 있었지만, 이제는 **다른 탭으로
  이동했다가 다시 들어오면 잠금 화면부터 다시 뜹니다** — 일반 직원 화면 옆에서
  잠깐 봐도 매출 내역이 계속 노출되지 않도록 하기 위해서입니다.
- **방문자·예약자 탭에는 매출금액 입력이 없습니다.** 등록 상품명만 남기고,
  실제 결제 금액은 오직 **매출·업무일지 탭**(비밀번호 보호)에서만 기록·열람합니다 —
  방문자 탭은 비밀번호 없이 누구나 보므로, 여기에 금액이 있으면 결국 매출이
  일반 직원에게 그대로 노출되기 때문입니다.

**운영 보드 사용법 — OT 관리 탭**
- **트레이너별 월 목표와 1~5주차 목표**를 "트레이너·목표 수정"에서 관리합니다
  (매출 카테고리와 같은 방식 — 미리 채워두면 주차가 바뀔 때 자동 적용).
  트레이너 추가/삭제도 여기서 합니다.
- **OT 진행 등록** 폼에 진행할 때마다 한 건씩 입력합니다: 담당 트레이너, 고객명,
  연락처, **회차**(1~4회차 이상), 진행상황(예약/진행중/완료/노쇼), 전환여부(미정/전환완료/미전환).
- **같은 회원의 2·3회차도 매번 새로 등록하세요.** 회차별 방문은 목록에 전부 남지만,
  "진행 인원"·달성률·전환율 같은 집계 수치는 **같은 트레이너+연락처(또는 이름)를
  자동으로 한 명으로 묶어서** 셉니다 — 한 사람을 3번 봤다고 3명으로 잡히지 않습니다.
  전환여부는 그 사람의 **가장 최근 회차 기록**을 기준으로 판정합니다.
- 위쪽 KPI와 카테고리 카드에 **이번 달·이번 주 목표/진행 인원/달성률**이 나란히
  나오고, 트레이너별 표에서도 월·주를 함께 볼 수 있습니다. 카드의 원형 게이지는
  매출 카드와 같은 방식입니다.
- 목록에서 **진행상황·전환여부를 그 자리에서 바로 수정**할 수 있습니다(드롭다운
  선택 즉시 저장). 월 선택·트레이너 선택·검색으로 걸러볼 수 있습니다.
- 개요 탭의 "이번 달 OT 누적" 타일도 이제 이 데이터를 그대로 씁니다 — 예전처럼
  손으로 적어 넣는 숫자가 아니라 실제 등록된 (중복 제거된) 인원 수입니다.

**운영 보드 사용법 — 회의록 탭**
- 주간 회의를 기록하는 곳입니다. **회의 종류는 대표–매니저 / 매니저–직원 두 가지**로
  구분해서 저장하고, 목록에서 종류별로 걸러볼 수 있습니다.
- 날짜, 참석자, 안건·논의 내용, 결정 사항, 다음 액션(할 일), 작성자를 기록합니다.
- 목록에서 **행을 클릭하면 회의 전문이 펼쳐집니다.** 월 선택·종류 선택·검색으로
  지난 회의도 바로 찾아볼 수 있습니다.

**운영 보드 사용법 — 근무·당직 탭**

이 탭은 **달력이 곧 입력 화면**이고, 그 아래가 집계 대시보드입니다.

- **달력에서 날짜를 누르면** 오른쪽 패널에서 그날의 **당직자 · 휴가 · 일정**을 바로
  넣고 뺄 수 있습니다. 입력하는 즉시 달력에 태그로 붙고, 아래 집계에 반영됩니다.
  - **당직자** — 선택하면 저장됩니다. "미배정"으로 되돌리면 배정이 지워집니다.
    "김지윤 → 김재연" 처럼 넘긴 경우는 최종 당직자를 고르고 경위를 인수인계 메모에 적습니다.
  - **휴가** — 월차/연차/휴무 중 고르고 직원명을 넣으면 추가됩니다.
  - **일정** — 동원훈련, 공사, 근무 시작일처럼 당직·휴가가 아닌 일도 적어 둘 수 있습니다.
- 달력에는 **2026년 공휴일**(첨부해 주신 '26년 휴일 정리' 시트 기준)이 함께 표시되고,
  다른 달 날짜를 누르면 그 달로 자동으로 넘어갑니다. **오늘** 버튼으로 이번 달에 돌아옵니다.
- **집계 대시보드** (달력 아래·위)
  - 맨 위 타일: **이번 주 당직** · 이번 달 당직 배정 · 미배정 주차 · 올해 월차 · 올해 연차
  - **주차별 당직 요약** — 그 달을 1주차~5주차로 나눠 누가 언제 당직인지 보여 줍니다.
    주차 기준은 첨부해 주신 스케줄표와 같은 **일요일 시작 ~ 토요일 끝**이고,
    이번 주에 해당하는 줄은 파랗게 표시됩니다.
    **한 주에 당직이 두 번**(예: 신정 1/1 목요일 + 토요일 1/3) 잡혀 있어도 둘 다 나옵니다.
  - **직원별 누적** — 그 해의 당직 횟수와 월차·연차·휴무를 사람별로 모아 줍니다.
  - **휴가 사용 내역** — 행을 누르면 달력의 그 날로 이동합니다.
- **직원 명단**은 쉼표로 구분해 저장하면 당직자 선택지와 직원명 자동완성에 반영됩니다.
- **"2026 달력 불러오기"** 버튼을 한 번 누르면 보내주신 스케줄표에서 읽어낸
  **당직 45건 · 휴가 9건 · 일정 8건**이 그대로 들어갑니다.
  같은 날짜는 덮어쓰므로 여러 번 눌러도 안전합니다.
- **개요 탭에는 "이번 주 당직"만** 맨 아래 칸에 나옵니다. 나머지 집계는 이 탭에서 봅니다.

**운영 보드 사용법 — 사물함 정리 탭**

목적은 하나입니다: **회원권 기간은 남아 있는데 사물함만 만료된 회원을 골라내는 것.**

1. 헬스장 프로그램에서 **사물함 관리**와 **유효 회원 목록**을 각각 엑셀로 내보냅니다.
2. 탭 위쪽 "엑셀 불러오기"에서 상자마다 **파일 선택** 버튼을 누르거나,
   파일을 상자 위로 **끌어다 놓습니다**. 파일을 읽으면 상자에 초록색으로
   파일명과 행 수가 표시됩니다. 두 개가 다 올라가면 **대조 분석하기**를 누릅니다.
   엉뚱한 파일을 올리면 어떤 열을 못 찾았는지 알려 줍니다.
3. 두 파일을 **회원번호로 맞춰 보고** 사물함마다 상태를 매깁니다.

| 상태 | 뜻 | 할 일 |
|---|---|---|
| **재등록 안내** | 회원권은 남았는데 사물함이 끝남 | 문자 보내서 사물함 재등록 유도 |
| **곧 만료** | 회원권·사물함 모두 유효하지만 사물함이 30일 안에 끝남 | 미리 안내 |
| **정리 대상** | 회원권까지 끝났는데 사물함을 점유 중 | 비우고 재배정 |
| **정상** | 둘 다 여유 있음 | – |
| **빈 칸** | 쓰는 사람 없음 | 배정 가능 |

- 대조는 **회원번호가 있으면 회원번호만** 봅니다. 회원번호가 있는데 유효회원 목록에
  없다는 것은 회원권이 끝났다는 뜻이므로, **동명이인에게 잘못 붙지 않도록 이름 대조는
  하지 않습니다** (사물함 파일에 회원번호가 아예 비어 있을 때만 이름으로 찾습니다).
- **안내 명단 CSV 내려받기**로 재등록 안내 대상 + 곧 만료 대상을 연락처까지 받아
  문자 발송에 쓸 수 있습니다 (엑셀에서 바로 열립니다).
- 각 행의 **발송대기/발송완료** 배지를 누르면 문자 보낸 사람을 체크해 둘 수 있고,
  이 체크는 다른 직원 화면에도 공유됩니다.
- 분석 결과는 저장되므로 **한 사람이 올리면 다른 직원 화면에도 바로 보입니다.**
  개요 탭에도 "사물함 재등록 안내 대상" 숫자가 나옵니다.
- 엑셀은 **브라우저 안에서만 읽습니다** (`public/vendor/xlsx.full.min.js`).
  파일 자체가 어딘가로 전송되지는 않고, 대조 결과만 우리 Firestore에 저장됩니다.
- 아래쪽 **직접 등록** 목록은 그대로 남겨 뒀습니다. 엑셀에 없는 사물함을 손으로
  관리할 때 쓰면 됩니다.

**기록 삭제** — 방문자·예약자, 문의DB, 업무일지, OT 진행 목록, 사물함, 회의록
모든 목록에 **삭제** 버튼이 있습니다. 누르면 확인창이 한 번 뜨고, 확인하면 바로
지워집니다 (되돌릴 수 없으니 주의하세요).

**급여 정산** — `payroll/state` 문서 **하나**에 전체 상태를 JSON 문자열로 저장합니다.
직원별 요율표(`brackets`)가 중첩 배열이라 Firestore 필드로는 그대로 못 넣기 때문입니다.

- 저장은 **저장/확정 버튼을 눌렀을 때**만 일어납니다. 입력만 하고 새로고침하면 사라집니다 (기존 동작과 동일).
- 화면 오른쪽 아래 배지에 `저장됨 / 저장 중 / 저장 실패` 가 표시됩니다.
- 내가 화면을 연 뒤 **다른 사람이 먼저 저장**했다면, 덮어쓰지 않고 "다른 사람이 먼저 저장했습니다" 를 띄웁니다.
  배지를 누르면 새로고침되고, 최신 데이터에서 다시 입력하면 됩니다.
- 로그인 중에는 다른 기기의 변경이 화면을 자동으로 갈아치우지 않습니다 (입력 중 날아가는 것 방지).
  대신 "다른 기기에서 변경됨 · 눌러서 새로고침" 배지가 뜹니다.

**급여 정산 화면 사용법 (매니저·직원 공통)**
- 로그인하면 이번 달이 열립니다. 오른쪽 위 **월 선택**에서 지난 24개월 중 아무 달이나 골라
  확인하거나, 확정 전이면 이어서 작성할 수 있습니다. 화면 아래 **지난 기록** 카드의 `열기` 로도 이동합니다.
- 달마다 상태가 남습니다: `작성중` → `제출` → (관리자가) `확정`.
- **제출하면 그 즉시 직원 화면이 잠깁니다.** 예전에는 제출 후에도 계속 고쳐서
  다시 제출할 수 있었지만, 이제는 "제출됨" 상태부터 직원 쪽 입력란이 모두
  비활성화되고 저장/제출 버튼도 사라집니다. 고칠 내용이 있으면 관리자가
  **"재작성 요청(직원에게 반려)"** 버튼으로 사유를 남기고 돌려보내야 하며,
  그래야 직원 화면이 다시 열립니다 — 직원 화면 상단에 관리자가 남긴 사유가
  그대로 표시됩니다. 확정된 달을 관리자가 "확정 취소(재오픈)" 할 때도 같은
  방식으로 사유를 남겨야 하며, 모든 재오픈 이력은 관리자 상세 화면 아래에
  날짜·사유와 함께 남습니다.
- **매니저(고범수) 정산은 세 항목으로 나뉩니다: ① 수업료 + ② 기본급 + ③ 매출 인센티브.**
  세 항목은 서로 완전히 독립이고, 화면에도 항목별 금액이 각각 표시된 뒤
  마지막에 세 항목의 합계·공제액·지급 급여가 나옵니다.
- **① 수업료**: 회원마다 고객명 · 분류 · 계약세션 · 결제금액 · 전월진행횟수 ·
  금월진행횟수를 입력하면, 잔여횟수 · 요율 · 회당단가 · 합산 수업료가 자동으로
  계산됩니다.
  - 요율: 등록 분류(신규 45% / 재등록 55% / 인계·지인·소개 50%)
  - **회당단가 = 결제금액 ÷ 계약세션 × 요율**
  - **합산 수업료 = 회당단가 × 금월진행횟수**
  - 예: 신규(45%), 계약 10회, 결제 100만원, 금월 4회 →
    회당단가 45,000원 · 합산 수업료 180,000원
- **② 기본급**: 매니저 본인이 직접 입력합니다.
- **③ 매출 인센티브**: **운영 보드와는 전혀 연동하지 않고 그 달 매출을 직접
  입력**합니다. 입력한 금액에 구간별 요율이 자동으로 적용됩니다.
  - 기본 구간: 1500만~1999만원 3% · 2000만~2499만원 5% · 2500만~2999만원 7%
    · 3000만원 이상 10% (구간·요율은 화면에서 행 추가/삭제까지 자유롭게 수정 가능)
  - **구간(요율) 판정은 입력한 매출 그대로 기준으로 하지만, 실제 지급액은
    "매출에서 부가세 10%를 먼저 뺀 금액 × 그 요율"로 계산합니다** —
    예: 2,800만원이면 7% 구간이 적용되고, (2,800만원 × 90%) × 7% = 1,764,000원.
- **매니저 본인 화면과 관리자 화면은 완전히 같은 화면**을 씁니다. 차이는 권한뿐입니다:
  본인은 제출하면 잠기고(관리자가 사유를 남기고 반려해야 다시 열림), 관리자는
  확정하기 전까지 세 항목 전부를 계속 고칠 수 있습니다.
- **이새한(트레이너) 총매출**: 수업 단가 × 이번 달 진행 횟수가 아니라, 그 달
  **실제로 받은 결제금액(총결제금액) 전체 합계**로 계산합니다.
- **이새한(트레이너) 수업료율 구간**: 0~299만원 30% · 300~399만원 45% ·
  400~499만원 50% · 500만원 이상 55%, 700만원을 넘는 금액에는 초과분의 10%가
  별도 인센티브로 추가됩니다(100만원당 10만원).
- **최민영(인포)은 3.3% 사업소득이 아니라 4대보험으로 공제합니다.** 다만 기존
  직장에서 고용보험에 가입되어 있어 **고용보험은 빼고 3대보험만** 공제합니다
  (산재보험은 전액 사업주 부담이라 급여에서 빠지지 않습니다):
  요율은 **세무사가 주는 고시 요율 표기 그대로** 입력합니다. 건강보험·장기요양은
  고시 요율이 노사 합산 값이라 **절반만** 공제하고, 국민연금은 관행대로
  본인부담률을 그대로 입력합니다.

  | 항목 | 입력하는 요율(기본값) | 실제 공제 |
  |---|---|---|
  | 국민연금 | 본인부담 **4.75%** (총 9.5%) | 공제 전 급여 × 4.75% |
  | 건강보험 | 총 **7.19%** | 공제 전 급여 × 3.595% (총 요율의 1/2) |
  | 장기요양보험 | 총 **0.9448%** | 공제 전 급여 × 0.4724% (총 요율의 1/2) |

  (장기요양 총 0.9448% = 건강보험료 7.19% × 13.14% 와 같은 값입니다.)
  요율은 해마다 바뀌므로 **관리자 화면에서 세 요율을 직접 고칠 수 있고**, 화면과
  급여명세서에는 "총 7.19% 중 본인부담 3.595%" 처럼 기준을 함께 표시해
  세무사가 준 숫자와 바로 대조할 수 있게 했습니다.
- **급여명세서 PDF (관리자 전용)**: 어떤 직원이든 그 달이 **확정** 상태가 되면
  관리자 상세 화면에 **"급여명세서 PDF 저장"** 버튼이 나타납니다. 누르면 인쇄
  창이 뜨고, 대상(프린터)을 **"PDF로 저장"** 으로 고르면 파일로 내려받습니다.
  명세서에는 성명·구분·지급 연월·확정일, 역할별 지급 내역(매니저는 세 항목,
  트레이너는 수업료·초과 인센티브, 인포는 기본급·주휴수당), 공제 내역
  (3.3% 또는 3대보험 항목별), 실지급액이 들어갑니다.

첫 실행 시 `payroll/state` 가 비어 있으면 `payroll.html` 안에 들어 있는 초기값(직원 3명, PIN `1234`)으로 자동 생성됩니다.
**배포 후 관리자 PIN과 직원 PIN을 바로 바꾸세요.**

## 4. 알아둘 것

**비용** — 4명 사용량은 무료(Spark) 한도(하루 읽기 5만 / 쓰기 2만 / 저장 1GiB) 근처도 안 갑니다.
카드 등록 없이 계속 무료로 쓸 수 있고, 한도를 넘으면 과금이 아니라 그날 요청이 막히는 방식입니다.

**보안 수준 (중요)** — 지금 설정은 *"링크를 아는 사람"* 기준입니다.
페이지가 자동으로 익명 로그인을 하므로, 주소를 아는 사람이 브라우저 개발자도구를 열면
급여 데이터까지 읽을 수 있습니다. PIN 화면은 앱 안에서만 막는 것이라 완벽한 방어가 아닙니다.
인터넷에서 무작위로 긁어가는 것은 막히지만, **주소를 받은 사람**은 마음먹으면 볼 수 있다고 생각하세요.

**보안 한 단계 올리기** (나중에 필요해지면)
1. Authentication → Sign-in method → **이메일/비밀번호** 사용 설정
2. 직원 4명 계정을 콘솔에서 직접 추가 (사용자 탭 → 사용자 추가)
3. `firestore.rules` 의 `signedIn()` 을 아래처럼 바꾸고 다시 배포

```
function signedIn() {
  return request.auth != null && request.auth.token.firebase.sign_in_provider == 'password';
}
```

4. 두 HTML 의 `signInAnonymously()` 를 이메일/비밀번호 로그인 화면으로 교체 (이 부분은 코드 수정이 필요합니다)

**백업** — Firestore 콘솔에서 데이터를 직접 보고 복사할 수 있습니다.
급여 데이터는 `payroll/state` 문서의 `data` 필드 하나만 복사해두면 통째로 백업됩니다.

**SDK 버전** — 두 HTML 상단이 `firebasejs/10.12.5` 를 가리킵니다.
버전을 올리고 싶으면 세 개의 `<script src>` 줄에서 숫자만 바꾸면 됩니다 (compat 빌드 유지 필요).

**기존 아티팩트** — 아티팩트 버전과 호스팅 버전은 **데이터가 서로 완전히 분리**됩니다.
아티팩트에 이미 쌓인 데이터가 있으면 옮겨오지 않으니, 옮기고 나면 한쪽만 쓰세요.

## 텔레그램 리포트 (일간 · 주간 · 월간)

운영 보드에 쌓인 매출·방문·문의·사물함·OT를 목표 달성률과 함께 텔레그램으로 자동 전송합니다.
GitHub Actions가 실행하므로 **추가 비용도, 카드 등록도 없습니다.**

| 리포트 | 보내는 때 | 다루는 기간 |
|---|---|---|
| **일간** | 매일 22:10 | 그날 하루 (+ 주·월 누계) |
| **주간** | 일요일 22:20 | 그 주 **월요일 ~ 일요일** 누적 |
| **월간 마감** | 말일 22:30 | 그 달 1일 ~ 말일 |

세 리포트 모두 `scripts/daily-report.mjs` 한 파일이 처리하고, `REPORT_KIND`
환경변수(`daily` / `weekly` / `monthly`)로 갈립니다. Firebase에 익명으로 접속해
**읽기만** 합니다. (설정값은 `public/firebase-config.js` 에서 자동으로 읽습니다.)

> cron 으로는 "말일"을 지정할 수 없어서, 월간은 **28~31일에 매일 실행하고 스크립트가
> 말일이 아니면 조용히 끝냅니다.** 그래서 한 달에 실제로 발송되는 건 한 번뿐입니다.

받는 메시지는 이런 모양입니다:

```
🏋️ M휘트니스 일일 리포트
2026-09-01 (화)
━━━━━━━━━━━━
💰 오늘 매출  700,000원
   신규 500,000원 · 재등록 200,000원
👣 방문/상담  1명 (등록완료 1명)
📞 문의전화   1건
🔒 사물함     신규 0 · 정리대상 0
⏱️ OT 진행    2명 (전환 1명)

📅 이번 주 누계  1,000,000원 (목표 7,000,000원 · 14%)
🗓️ 이번 달 누계  2,000,000원 (목표 30,000,000원 · 7%)
🏋️ 이번 주 OT 달성률  25% (2/8명 · 전환 1명)
🏋️ 이번 달 OT 달성률  7% (2/30명 · 전환 1명)
```

주간 리포트는 이런 모양입니다 — **하루하루가 어떻게 쌓였는지 누적으로** 보여 줍니다:

```
📊 M휘트니스 주간 리포트
2026-08-31(월) ~ 2026-09-06(일)
━━━━━━━━━━━━
💰 주간 매출  2,326,500원 (목표 4,000,000원 · 58% ⚠️)

📅 일자별
   월 08-31   0원   누적 0원  (일지 없음)
   화 09-01   1,633,500원   누적 1,633,500원
   수 09-02   660,000원   누적 2,293,500원
   목 09-03   33,000원   누적 2,326,500원
   ...

🏷️ 카테고리별
   고범수 매니저 (PT)  500,000원 / 500,000원 · 100% ✅
   퍼블릭 (헬스 회원권)  1,826,500원 / 2,500,000원 · 73%
   ...

👣 방문/상담  4명 · 등록완료 4명 (전환 100%)
📞 문의전화   11건
⏱️ OT 진행    2명 (전환 0명) · 목표 2명 · 100% ✅
🔒 사물함     재등록 안내 19명 · 곧 만료 29명 · 정리 대상 90명
🗓️ 이번 주 당직  이새한

🗓️ 이번 달 누계  2,326,500원 (목표 21,000,000원 · 11% ⚠️)
```

월간 마감 리포트는 여기에 **주차별 매출**과 사물함 전체 현황이 더 붙습니다.

- 달성률 옆 표시: **✅ 100% 이상**, 표시 없음 70% 이상, **⚠️ 70% 미만**.
- 주 기준은 **월요일 시작**입니다 (매출·업무일지 탭과 같은 기준). 근무·당직 탭의
  달력은 기존 스케줄표에 맞춰 일요일 시작이라 서로 다릅니다.
- **주는 달 경계에서 잘립니다.** 아래 "주차를 세는 법" 참고.
- OT는 여기서도 같은 회원의 여러 회차를 인원 1명으로 묶어서 셉니다.
  OT 달성률 줄은 OT 관리 탭에서 트레이너 목표(월 또는 주)를 하나라도 설정해야 나타납니다.
- 사물함 줄은 **사물함 정리 탭에서 엑셀을 한 번이라도 대조**해야 나타납니다.

### 주차를 세는 법 (달 경계에서 자릅니다)

한 주가 달을 걸치면 **그 달 몫만** 그 달 리포트에 들어갑니다.
예를 들어 8/31(월)~9/6(일) 주는 이렇게 나뉩니다.

| | 기간 | 어디에 들어가나 |
|---|---|---|
| **8월 6주차** | 8/31 하루 | 8월 월간 마감 리포트 (8월의 마지막 줄) |
| **9월 1주차** | 9/1 ~ 9/6 | 9월 첫 주간 리포트 · 9월 월간 리포트 |

- 그 달에 걸치는 월~일 주들을 **순서대로 1주차부터** 매기고, 각 주의 범위를 그 달 안으로
  자릅니다. 그래서 **주차별 매출을 다 더하면 정확히 월 매출**이 됩니다.
- 달을 걸친 주에는 **예전 이름을 괄호로 같이 적습니다**. 위 예에서 9월 1주차 옆에는
  `(8월 5주차)` 가 붙습니다 — 예전 규칙(그 주 월요일이 속한 달 기준)에서 부르던 이름입니다.
- 달 첫날이 주 중간이면 **그 달 주차가 6개까지** 나올 수 있습니다 (2026년 8월이 그렇습니다:
  8/1이 토요일이고 31일까지 있어서 1주차가 8/1~8/2 이틀뿐입니다). 목표는 1~5주차 칸까지만
  설정할 수 있어서 **6주차는 "목표 칸 없음"** 으로 표시됩니다. 5주차 목표를 두 번 쓰지 않기
  위해서입니다.
- **운영 보드 화면(매출·업무일지 탭)도 같은 규칙**을 씁니다. "이번 주 매출"과 "이번 주 목표"가
  리포트와 어긋나지 않도록 맞춰 두었습니다.

### 월간 리포트를 "말일"에 보내는 방법

GitHub Actions 의 `schedule` 은 **POSIX 5칸 cron** 만 받습니다. Quartz(Jenkins 등)에서 쓰는
`L`(마지막 날), `W`, `#` 같은 표기는 지원하지 않아서 `0 0 L * *` 같은 건 쓸 수 없습니다.

그래서 **28~31일에 매일 실행하고, 스크립트가 말일이 아니면 발송 전에 조용히 끝냅니다.**
(`scripts/daily-report.mjs` 의 `lastDayOfMonth` 검사) 이게 이 제약의 표준 우회법입니다.

- 실제 발송은 **한 달에 정확히 한 번**입니다.
- 헛도는 실행이 한 달에 2~3번 생기지만, 체크아웃 후 몇 초 만에 끝나서
  Actions 사용량은 사실상 0입니다.

바꾸고 싶으시면 **말일 대신 다음 달 1일 22:30에 보내는 방법**도 있습니다
(cron `30 13 1 * *`). 실행이 딱 12번으로 줄고, 무엇보다 **달이 완전히 끝난 뒤에 집계**하므로
말일 22:30 이후에 쓴 업무일지도 빠짐없이 들어갑니다. 대신 리포트가 하루 늦게 옵니다.
원하시면 한 줄만 바꾸면 됩니다.

**직접 보내보기** — GitHub 저장소 → Actions → "운영 리포트 (텔레그램)" → Run workflow →
`kind` 에서 daily/weekly/monthly 를 고르고 실행합니다. `dry_run` 에 `1` 을 넣으면
전송하지 않고 실행 로그에서 내용만 확인할 수 있습니다. 수동 실행은 월간의 말일 검사도
건너뛰므로 아무 때나 미리 볼 수 있습니다.

### 준비 (한 번만, 약 5분)

**1. 텔레그램 봇 만들기**
1. 텔레그램에서 **@BotFather** 를 검색해 대화 시작
2. `/newbot` 입력 → 봇 이름과 아이디를 정하면 **토큰**을 줍니다
   (예: `8123456789:AAH...xyz` — 이게 `TELEGRAM_BOT_TOKEN`)
3. 방금 만든 봇을 검색해 들어가서 아무 메시지나 한 번 보냅니다
   (봇이 나에게 먼저 말을 걸 수 없어서, 내가 먼저 말을 걸어줘야 합니다)

**2. 내 chat id 알아내기**
1. 텔레그램에서 **@userinfobot** 을 검색해 대화 시작 → `/start`
2. 답으로 오는 숫자(예: `123456789`)가 내 chat id 입니다 (이게 `TELEGRAM_CHAT_ID`)
   - 여러 명이 받으려면: 텔레그램 그룹을 만들고 내 봇과 @userinfobot 을 초대,
     그룹에서 나온 **마이너스로 시작하는 숫자**(예: `-1001234...`)를 chat id 로 쓰세요.

**3. GitHub에 비밀값 2개 저장**
1. https://github.com/jiyoon7653/mfitness/settings/secrets/actions 접속
2. **New repository secret** 을 눌러 두 개를 각각 추가:
   - 이름 `TELEGRAM_BOT_TOKEN`, 값: 1번에서 받은 토큰
   - 이름 `TELEGRAM_CHAT_ID`, 값: 2번에서 받은 숫자

### 바로 테스트해 보기

1. https://github.com/jiyoon7653/mfitness/actions 접속
2. 왼쪽에서 **운영 리포트 (텔레그램)** 선택 → 오른쪽 **Run workflow**
3. `kind` 에서 daily / weekly / monthly 중 하나를 고르고 실행하면 텔레그램으로 바로 옵니다.
   보내지 않고 로그로만 미리보려면 `dry_run` 칸에 `1` 을 넣고 실행하세요.

정상이면 일간은 매일 밤 10시 10분, 주간은 일요일 10시 20분, 월간은 말일 10시 30분에
자동으로 옵니다. 별도로 켜둘 것은 없습니다.

### 참고
- GitHub Actions 예약 실행은 서버가 붐빌 때 몇 분 늦을 수 있습니다(드묾).
- 저장소에 **60일간 아무 변화가 없으면 예약 실행이 자동 중지**됩니다.
  가끔(2개월에 한 번쯤) 코드를 조금 바꿔 올리거나, Actions 화면에서 워크플로를
  다시 활성화하면 됩니다.
- 발송 시각을 바꾸려면 `.github/workflows/daily-report.yml` 의 `cron: '10 13 * * *'`
  에서 시간을 조정하세요(UTC 기준, 한국시간 −9시간. 예: 21시 발송 = `0 12 * * *`).
- 텔레그램 봇 토큰은 비밀번호입니다. GitHub Secret 에만 넣고 코드/채팅에 붙여넣지 마세요.
